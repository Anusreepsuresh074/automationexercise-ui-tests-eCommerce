## Existing UI test/framework setup
- Framework: Playwright (Python) `1.63.0`, pytest `9.1.1`, `allure-pytest` `2.16.1` — all pinned in `requirements.txt` (built this session by `create-ui-framework-structure`, not pre-existing).
- Test layout: Page Object Model planned under `src/pages/` (currently empty — no real pages generated yet); spec files planned under `tests/<flow>/` (currently empty).
- Config/fixtures: `config/config.yaml` (base URL per env, browser/viewport/timeouts); root `conftest.py` (`--env`/`--browser` CLI options, session-scoped Playwright instance); `tests/conftest.py` (browser/context/page fixtures; a cached-login fixture slot is noted but intentionally not implemented — that's `get-ui-auth`'s job).
- Locator contract: **the app itself exposes a consistent `data-qa` attribute convention** on the Login, Signup, and Contact Us forms (`data-qa="login-email"`, `data-qa="signup-name"`, `data-qa="name"`, etc.) — this should be the primary locator strategy site-wide. Product-grid/cart/review-form elements don't use `data-qa`; fall back to `id`/`name` (`#quantity`, `#product_id`, `#review`) or a stable class + `data-product-id` combination (`a.add-to-cart[data-product-id="N"]`) there instead.
- Gaps noted: no page objects or tests generated yet (expected — `ui-test-automation`'s job). Checkout, account, and logout pages remain unconfirmed per the table above.

## Open questions / follow-ups
- **Signup's second step** (account details after the initial name+email submit) — not confirmed live since submitting a form is outside this skill's look-and-snapshot permission. `get-ui-auth` should confirm this directly as part of resolving the signup/login flow.
- **Non-empty cart table and full checkout flow** (address, payment, order confirmation) — same reason; requires adding a real item and being logged in. Needs live confirmation during `ui-test-automation`'s execution phase, or an explicit one-off permission grant to drive it now.
- **Account management pages and `/logout`** — unconfirmed for the same reason (requires an active session).
- **Console errors present on every page (3–20 per page)** — DOM inspection found `data-google-vignette`/`data-google-interstitial` attributes on injected anchor tags, strongly suggesting these are third-party ad/vignette script noise rather than app bugs. Recommend the test suite does **not** assert on zero console errors for this site; flagging for a human decision rather than deciding unilaterally.
- **Add-to-cart button on the product-details page has no `id`/`data-qa`** (only `type="button"` + visible text "Add to cart") — will need a text/role-based locator or a `nth`/scoped selector, less resilient than the `data-qa` pattern used elsewhere. Worth a deliberate choice in `ui-test-automation` rather than an accidental one.
