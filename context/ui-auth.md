## Session shape in the browser

- **Session cookie:** `sessionid`, domain `automationexercise.com`, **httpOnly: true**, secure: false, sameSite: Lax — confirmed via `page.context().cookies()` (not `document.cookie`, which correctly can't see it since it's httpOnly). Tests cannot read this cookie's value directly from page JS; they can only rely on Playwright's own storage-state capture/restore, which works regardless of httpOnly.
- **Other cookies present:** `csrftoken` (readable, not httpOnly) plus a large number of third-party ad-network tracking cookies (`__gads`, `doubleclick.net`, `criteo.com`, `adform.net`, etc.) — unrelated to auth, safe to ignore in any session-state comparison.
- **localStorage/sessionStorage:** no auth-related keys found — only `google_adsense_settings` / `google_ama_config` (ad-tech), unrelated to the session.
- **Post-login redirect target:** `/` (Home) — confirmed for both a fresh login and the post-signup auto-login.
- **On-page "logged in" signal (in priority order):**
  1. `a[href="/logout"]` visible in nav (most resilient — a real selector, not text matching)
  2. Text "Logged in as {name}" visible in nav (human-readable but only a text match — the name portion is dynamic, so assert on the prefix "Logged in as" rather than the full string)

## Session storage & reuse recommendation

Log in once per test session (or per pytest-xdist worker) and reuse the resulting Playwright `storage_state()` — this captures the httpOnly `sessionid` cookie correctly even though page JS can't read it directly, so there's no need to know its value, just to save/restore it as a unit. Recommended shape:

- A session-scoped fixture (e.g. `authenticated_state` in `tests/conftest.py`, the placeholder slot `create-ui-framework-structure` already left) that: launches a context, drives the real `/login` flow once using `TEST_EMAIL`/`TEST_PASSWORD` from `.env`, calls `context.storage_state(path="auth/state.json")`, and closes.
- Per-test `context`/`page` fixtures then create their browser context with `storage_state="auth/state.json"` instead of repeating the UI login for every test.
- Verify the saved state actually works by asserting `a[href="/logout"]` is visible immediately after restoring it — cheaper and more resilient than re-checking the full "Logged in as" text.

## Session staleness (token expiry mid-run)

Not applicable in the usual sense — there's no visible token with a documented expiry (no `context/api-auth.md`, no JWT found in storage). Django session cookies for a site like this typically last well beyond a single test run (commonly on the order of weeks), so a full suite run outlasting it is unlikely. If a test unexpectedly lands back on `/login` instead of the page it expected, treat that redirect itself as the staleness signal — re-run the login flow and re-save `storage_state()` rather than assuming a bug in the test.
